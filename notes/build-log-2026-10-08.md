## Gaps the plan did not cover

1. **Getting a shell from the laptop.** No SSH key existed. `ssh-copy-id` cannot run from a
   non-interactive prompt (no askpass). Pasting a one-line `echo '...' >> authorized_keys` into the
   server shell failed twice because the terminal wrapped the key across lines inside the quotes.
   What worked: four short lines, the key in a shell variable:
   `K=AAAA...`, then `echo "ssh-ed25519 $K oll@omarchy" >> ~/.ssh/authorized_keys`.
2. **sudo asks for a password**, so nothing can be scripted over SSH. Added
   `/etc/sudoers.d/srv1-nopasswd` with `srv1 ALL=(ALL) NOPASSWD: ALL`. The same line-wrap problem
   broke the first attempt (`sudo` ran with no arguments). File must be mode 440; `visudo -c` to check.
3. **Cloudflare API token** was a one-line instruction in the plan. Real path: dash.cloudflare.com →
   profile icon → My Profile → API Tokens → Create Token → template "Edit zone DNS" → Use template →
   permissions Zone/DNS/Edit (prefilled) + Add more: Zone/Zone/Read → Zone Resources: Include /
   Specific zone / 22112002.xyz → Continue to summary → Create Token → copy once. Never the Global API Key.

## Listeners: the step that disappeared (12:50)

The plan added loopback listeners on 143 and 587 for Roundcube. Not needed. The NetworkListener
reference says `overrideProxyTrustedNetworks` enables PROXY protocol only for connections *from*
the listed networks, so when the VPS is trusted in part 08, Roundcube's loopback connections to the
same 993/465 listeners stay plain. Changed `config.inc.php` to `ssl://127.0.0.1:993` and
`ssl://127.0.0.1:465`. `openssl s_client -verify_hostname mail.22112002.xyz` against 127.0.0.1
passes on 993, 465 and 4190 with the wildcard certificate, so `peer_name` does its job.
Listeners after the wizard remain: smtp *:25, submissions *:465, imaptls *:993, pop3s *:995,
managesieve *:4190, https *:443, http *:8080. Binding them to the Tailscale IP is deferred to part 08.

## Change of plan: no VPS (14:30)

The user has no budget for a VPS. Investigation (GitHub + Cloudflare docs) found a zero-cost design:
- Inbound: Cloudflare Email Routing (free) → Email Worker → **Workers VPC** (beta, free on all plans:
  a Worker can `connect()` raw TCP to any address reachable through an existing Cloudflare Tunnel)
  → cloudflared on srv1 → Stalwart :25. Existing project: github.com/Lumysia/email-smtp-bridge
  (AGPL, ~100 lines, written for Stalwart). Cloned into `worker/` in this repo; `wrangler.jsonc`
  now points at tunnel 0cf125dc-… and `SMTP_ADDRESS=127.0.0.1:25`. Typechecks with wrangler 4.148.
- Outbound: Stalwart Relay route → Resend SMTP (free: 100/day, 3000/month, custom domain, DKIM,
  no branding). Measured from srv1: 587/465/2525 outbound open, 25 filtered.
- Phones: JMAP over HTTPS through the tunnel (Twake Mail, Sterna Mail, Ltt.rs). User refused a
  VPN app on phones. Free TCP tunnels for IMAP ruled out (playit.gg now paid for generic TCP).
- Ruled out: Workers inbound TCP (private beta), Cloudflare Email Service sending (Workers Paid
  $5/mo), Gmail "Send as" (Google ends it Jan 2027), Oracle free tier (no PTR, reclaimable).
