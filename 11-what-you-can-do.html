What You Can Do With It

A mailbox on my own domain, on my own machine, with a programmable front door and an API-driven relay, can do much more than receive newsletters. This page lists what it is good for, starting with the uses that need no new software and ending with the ones that need code.

Written 11 October 2026 against the as-built design: Stalwart 0.16.25 on srv1, Cloudflare Email Routing with a catch-all to the Worker, Resend's free plan for sending. Every send counts against Resend's 100 a day and 3,000 a month.

1. An address for every service

The Email Routing rule is a catch-all: Cloudflare hands every address at 22112002.xyz to the Worker, and Stalwart decides what exists. That makes addresses free:

  • Plus addressing: sign up as olwethu+bank@22112002.xyz or olwethu+shop@22112002.xyz. Stalwart delivers it to olwethu@, and the To: header shows which service leaked or sold the address.
  • Aliases: add postmaster@, abuse@, admin@, hello@ as aliases on my account in the Stalwart admin UI. The first two are expected by other mail operators, and postmaster@ receives the DMARC and TLS reports (part 10, section 3).
  • A domain catch-all in Stalwart: optionally, deliver any unknown local part to one mailbox. Then netflix@22112002.xyz works without setting anything up first. The cost is more spam once the domain is on lists, so plus addressing is the tidier choice.
  • Burner addresses: when an address starts receiving spam, reject it in Stalwart or Sieve. Nothing else breaks.
Portable identity

Accounts registered to @22112002.xyz survive a change of provider. If Stalwart, Cloudflare or Resend ever goes away, the MX and the relay change, and the address stays the same.

2. Server-side filters with Sieve

Stalwart runs Sieve scripts at delivery, and its ManageSieve listener is already up on 4190. Roundcube's managesieve plugin gives a point-and-click editor for rules that run on the server, so they apply to every client, phone included:

require ["fileinto", "subaddress", "envelope"];
# olwethu+anything@ goes to a folder named after the tag
if envelope :detail "to" "bank"  { fileinto "Finance"; stop; }
if envelope :detail "to" "shop"  { fileinto "Receipts"; stop; }
# trusted transactional senders never go to Junk
if address :domain "from" ["anthropic.com", "claude.com", "github.com"] { fileinto "INBOX"; stop; }

The last rule is a stopgap for part 10's Junk problem while the real fix is made.

3. Alerts from the homelab

The most useful mail this server sends will be to me. Every machine on the tailnet can submit through Stalwart over Tailscale on 465, so homelab alerts arrive DKIM-signed from my own domain instead of from an unknown host:

  • Proxmox: Datacenter › Notifications › add an SMTP target: 100.72.72.58 port 465, TLS, user alerts@22112002.xyz. Backup job failures and disk SMART warnings then reach the inbox.
  • Debian on srv1: unattended-upgrades reports, cron MAILTO= output and systemd OnFailure= units, through a small sendmail-compatible client (msmtp) pointed at 127.0.0.1:465.
  • Uptime Kuma or healthchecks.io: both can notify by SMTP. That gives part 10's canary somewhere to report.

Make a separate Stalwart account (or an app password) for alerts, so a leaked credential on one machine can be revoked without touching my own login.

4. Sending from scripts and apps

Anything I build (the LMS on lms.22112002.xyz, a contact form, a side project) can send real mail from the domain. There are two ways in, and each needs a different key:

CredentialA Stalwart account or app passwordA Resend API key with Sending access, scoped to 22112002.xyz
Where to create itStalwart admin › the account › app passwordsresend.com › API Keys › Create API key (one key per app)

Good forHomelab apps, anything on srv1Apps hosted elsewhere, delivery webhooks, bounce tracking

An HTTP send is one request:

curl -s https://api.resend.com/emails \
  -H "Authorization: Bearer $RESEND_API_KEY" \
  -H 'Content-Type: application/json' \
  -d '{"from":"LMS <noreply@22112002.xyz>","to":["someone@example.com"],
       "subject":"Your account","text":"Welcome."}'
Keys are per purpose

The existing Resend key named stalwart is Stalwart's relay password. Do not reuse it in an app: create a new key per app, so one can be revoked without stopping all outbound mail. Keep keys in an env file or a Worker secret (wrangler secret put), never in this repo.

5. Calendars, contacts and files

Stalwart is more than a mail server: it also serves CalDAV (calendars), CardDAV (contacts) and WebDAV (files) for the same accounts. That is a replacement for Google Calendar and Contacts, on hardware I own. The endpoints sit under https://mail.22112002.xyz/dav/, published through the existing tunnel and Caddy like JMAP. Phones connect with DAVx⁵ on Android or the built-in account settings on iOS. Before relying on it, confirm on 0.16.25 that the /dav paths answer through Caddy and are not blocked by the Caddy block that hides /admin.

6. Mail as a trigger: more from the Worker

Every inbound message already runs through code I control before it reaches Stalwart. That Worker can do more than relay:

  • Notify a phone: for mail to a chosen address, also post the subject and sender to a Telegram bot or a Discord webhook. A push notification without a mail app.
  • Mail-to-task: mail to todo@ turns into a row in a database or a task, parsed with the postal-mime library.
  • Reject at the edge: refuse known-bad senders with message.setReject() before they cost a tunnel round trip.
  • Fallback forward: the outage protection in part 10, section 2.

Each of these sits beside the delivery to Stalwart, not in place of it, so the mailbox stays the record of everything that arrived.

7. Mailboxes for other people

Stalwart can host more accounts and more domains at no extra cost: a family member's address, or a second domain with its own Email Routing rule pointing at the same Worker. Two limits apply:

  • Resend's free plan covers the whole server. 100 messages a day are shared between everyone. Several active users would need the paid plan, or a second relay chosen by sender in Stalwart's routing strategy.
  • The server becomes their mail provider. An outage at home or a lost disk now affects someone else. Do part 10's fallback forward and off-site backups before adding anyone.

8. As a lab

A working mail server is a good place to learn the parts of the internet most people never see: read DMARC aggregate reports to find out who sends as the domain, try MTA-STS and watch TLS-RPT reports arrive, write Sieve, read raw headers until the authentication results make sense at a glance. The series so far is the notes; this part is the to-do list.

Glossary for this part

Plus addressing
Adding +tag to the local part (olwethu+bank@). The server delivers it to the base address, and Sieve can read the tag as the :detail part.
App password
A second password on a mail account, for one device or app, which can be revoked on its own.
Resend API key
A bearer token for Resend's HTTP API and SMTP relay. Scoped to sending, and optionally to one domain.
CalDAV / CardDAV
Open protocols for syncing calendars and contacts over HTTPS. What Google, Apple and Stalwart all speak underneath.
msmtp
A small SMTP client that behaves like sendmail, so cron, scripts and system tools can send through Stalwart.
