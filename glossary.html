Glossary

Every term from the series in one place, in the plain words I would use to explain it to someone else. The number after each term is the part where it first matters.

Alphabetical. Commands are listed under their own names.
A / AAAA record · 01
The DNS record that maps a hostname to an IPv4 (A) or IPv6 (AAAA) address. The MX record must point at a hostname that has one of these; mine is mail.22112002.xyz → the VPS's public IP.
ACME · 04
The protocol Let's Encrypt and other certificate authorities use to issue certificates automatically. The server proves it controls the name, the CA hands over a certificate, and the whole thing repeats before expiry without me doing anything.
Aggregate report · 03
A daily XML summary that receivers send to the address in your DMARC record, listing every IP that sent mail claiming to be your domain and whether it passed. The way you find out who is sending as you.
Alignment · 03
DMARC's extra requirement: it is not enough for SPF or DKIM to pass, the domain they passed for must match the domain in the visible From header. Stops someone passing SPF for their own domain while displaying mine.
Autoconfig / autodiscover · 07
DNS records and small web endpoints that let Thunderbird (autoconfig) and Outlook (autodiscover) fill in server settings from just an email address. Stalwart publishes them.
Bootstrap mode · 04
What Stalwart does on first start with no config.json: listens on port 8080 with only the web admin, prints a one-time admin password to the log, and waits for the setup wizard to be completed.
Bounce · 02
A message the sending server gives up on and returns to the sender with the reason, after a permanent 5xx reply or after retrying a 4xx for too long.
CAA record · 03
A DNS record saying which certificate authorities may issue certificates for the domain. Stalwart publishes one naming Let's Encrypt.
Caddy · 01
The web server already on srv1. In this series it serves Roundcube and, optionally, the MTA-STS policy, both behind the Cloudflare Tunnel. It has nothing to do with SMTP or IMAP.
CGNAT · 01
Carrier-grade NAT: my ISP shares one public IP across many customers, so I have no public address of my own and nothing on the internet can start a connection to my house. The premise of the whole series.
Cloudflare Tunnel · 01
An outbound connection from cloudflared on my VM to Cloudflare, down which Cloudflare relays web requests. It carries HTTP and HTTPS only, which is why it publishes my websites and cannot publish a mail server.
Deferred · 02
A message the sending server could not deliver right now (a 4xx reply, or no connection) and has put back in its queue to retry later.
dig · 09
The DNS lookup tool. dig MX domain, dig A host, dig -x ip for reverse, dig TXT name for SPF, DKIM and DMARC. @1.1.1.1 asks a specific resolver.
DKIM · 03
DomainKeys Identified Mail. The sending server signs each message with a private key; the public key sits in DNS under a selector. The receiver verifies the signature, proving the message came from a server holding my key and was not altered in transit.
DMARC · 03
A DNS policy that ties SPF and DKIM to the From header (alignment) and tells receivers what to do when both fail: nothing (p=none), junk it (quarantine) or refuse it (reject). Also where the aggregate reports get sent.
DNS-01 · 04
The ACME challenge where the server proves control of a name by writing a TXT record into its DNS zone. Needs no open ports at all, which is why it is the right one for a server behind CGNAT. Stalwart does it through the Cloudflare API.
DNSBL · 03
DNS-based blocklist. A receiving server looks up the connecting IP in a list such as Spamhaus by doing a DNS query; a hit means "this address has sent spam" and the connection is refused or scored down.
DNSSEC · 03
Cryptographic signatures on DNS records so a resolver can tell they were not forged. Required for DANE. Not part of this build; a later project.
DANE / TLSA · 03
DNS-based Authentication of Named Entities: a TLSA record pins which certificate the mail server should present, so a sender can refuse a connection with a different one. Only trustworthy with DNSSEC, which I do not have yet.
Envelope vs header · 02
The envelope is what the servers say to each other in SMTP (MAIL FROM, RCPT TO). The headers are inside the message (From:, To:). They can differ, and SPF checks the envelope while DMARC checks the header.
FCrDNS · 03
Forward-confirmed reverse DNS: the PTR of the connecting IP names a host, and that host's A record is the same IP. One of the first things a receiver checks, and the reason the VPS needs an editable PTR.
Greylisting · 03
A receiving server deliberately replying 4xx the first time it sees a new sender, on the theory that real servers retry and spam tools do not. Why a first message to a new domain can take fifteen minutes.
Grey cloud / DNS only · 05
A Cloudflare DNS record that resolves to the real IP, not to Cloudflare's proxy. The mail A record must be grey; every other record in the zone is orange, which is what makes this the easiest mistake to make.
HAProxy · 05
From the VPS design in the original part 05, never built. The load balancer and proxy running on the VPS. Here it works in TCP mode: it accepts connections on the public 25, 465 and 993 and forwards the raw bytes to Stalwart over Tailscale, adding a PROXY protocol header.
IMAP · 02
The protocol a mail client uses to read a mailbox that stays on the server: folders, flags, search. Port 993 with implicit TLS for the public, 143 on loopback for Roundcube.
Implicit TLS vs STARTTLS · 02
Implicit: the connection is TLS from the first byte (ports 465, 993). STARTTLS: the connection starts in plain text and upgrades on request (port 25, 587, 143). Server-to-server mail on 25 is always STARTTLS, because the other side may not support TLS at all.
JMAP · 04
A modern JSON-over-HTTPS replacement for IMAP and the client side of SMTP, built by the same community that runs Fastmail. Stalwart speaks it natively; few clients do yet.
Let's Encrypt · 04
The free certificate authority everything here uses, through ACME.
MagicDNS · 07
Tailscale's feature that gives every device a name (srv1, pve) resolvable from any other device in the mesh.
mail-tester · 08
mail-tester.com: send a message to a one-time address and get a score out of ten with every deduction explained. The quickest outside opinion on deliverability.
ManageSieve · 04
The protocol for uploading Sieve filter scripts to the server from a client. Port 4190. Stalwart supports it; Roundcube has a plugin for it.
MDA · 02
Mail delivery agent: the component that takes a message the MTA has accepted and writes it into the right mailbox. In Stalwart it is not a separate program.
MSA · 02
Mail submission agent: the server a mail client hands outgoing mail to, after authenticating. Ports 465 or 587. The same software as the MTA but a different door with different rules.
MTA · 02
Mail transfer agent: the server-to-server part. Accepts mail from other MTAs on port 25 and delivers outgoing mail to other MTAs by looking up their MX. Postfix, Exim and Stalwart's SMTP component are MTAs.
MTA-STS · 03
A DNS record plus a policy file served over HTTPS saying "always use TLS when delivering to me, and expect this certificate name". Stops a downgrade to plain text. The policy file can be served through the Cloudflare Tunnel because it is just HTTPS.
MUA · 02
Mail user agent: the program a person reads and writes mail in. Thunderbird, the phone's mail app, Roundcube.
MX record · 01
The DNS record naming which host accepts mail for a domain, with a priority number. 22112002.xyz MX 10 mail.22112002.xyz. Must name a host with an A record, never a proxied one.
nc · 09
netcat. nc -vz host port opens and closes a TCP connection, proving the path works without speaking any protocol.
Open relay · 05
A mail server that will forward anyone's mail to anyone. Found and abused by spammers within hours; the IP's reputation is then gone. Postfix's mynetworks and reject_unauth_destination exist to prevent this.
openssl s_client · 09
Makes a TLS connection by hand and prints the certificate chain. -starttls smtp for port 25; plain for 465 and 993; -servername so the server knows which certificate to present.
PBL · 01
Spamhaus Policy Block List: IP ranges whose owners have declared them end-user space that should never send mail directly. Residential and mobile ranges are on it, which is one reason mail cannot leave from home.
PHP-FPM · 06
The PHP process manager already on srv1 for the LMS. Roundcube is a PHP application and runs in it.
POP3 · 02
The older mailbox protocol that downloads and usually deletes. Stalwart supports it; I am not enabling it.
Postfix · 05
From the VPS design in the original part 05, never built. The classic open-source MTA. On the VPS it does one thing: accept outbound mail from srv1 over Tailscale and deliver it to the world from the VPS's public IP.
PROXY protocol · 05
From the VPS design in the original part 05, never built. A header HAProxy prepends to a forwarded connection carrying the original client's IP and port. Without it Stalwart would see every inbound connection as coming from the VPS. The receiving side must be told which addresses it may trust to send one.
PTR record · 01
Reverse DNS: the hostname an IP address claims. Set by whoever controls the IP block, so it is set in the VPS provider's console, not in Cloudflare.
Queue · 02
Where an MTA keeps messages it has accepted but not yet delivered. A healthy queue is nearly empty; a message sitting in it for hours is a fault to chase.
Reply codes · 02
The three-digit numbers an SMTP server answers with. 2xx success, 3xx "go on" (after DATA), 4xx temporary failure (retry later), 5xx permanent failure (bounce).
RocksDB · 04
The embedded key-value database Stalwart uses by default to store everything: configuration, accounts, messages, indexes. One directory under /var/lib/stalwart, no separate database server.
Roundcube · 06
Open-source webmail in PHP. It is an IMAP and SMTP client that happens to run in a browser; it holds no mail of its own.
Selector · 03
The label that picks which DKIM key a message was signed with: selector._domainkey.domain. Lets a domain have several keys and rotate them.
Sieve · 04
The standard server-side mail filtering language ("if subject contains X, file into folder Y"). Stalwart runs Sieve scripts at delivery.
Smarthost / relay · 05
A server that another mail server hands all its outbound mail to, instead of delivering directly. Postfix on the VPS is Stalwart's smarthost.
SMTP · 02
Simple Mail Transfer Protocol: the line-by-line conversation (EHLO, MAIL FROM, RCPT TO, DATA) used both for clients submitting mail and for servers handing it to each other.
SPF · 03
Sender Policy Framework: a TXT record listing which IPs may send mail for the domain. v=spf1 mx -all means "only the hosts in my MX record, refuse everything else". The receiver checks the connecting IP against it.
SRV record · 03
A DNS record advertising which host and port provide a service, used by some clients to discover IMAP and submission servers. Stalwart publishes them.
ss -tlnp · 09
Lists every listening TCP socket with its address, port and owning program. The fastest way to answer "is anything actually on that port".
Stalwart · 04
The mail server. One binary written in Rust that is the MTA, MSA, MDA, IMAP, JMAP, POP3 and ManageSieve server, spam filter, and web admin, configured through its WebUI and stored in RocksDB. Runs on srv1.
Submission · 02
A mail client handing an outgoing message to its own server, with authentication. Port 465 (implicit TLS) or 587 (STARTTLS). Distinct from server-to-server transfer on 25.
swaks · 09
Swiss Army Knife for SMTP: a command-line client that has a complete SMTP conversation and prints every line. The quickest way to see exactly what a server replies.
Tailscale · 01
The WireGuard-based mesh that already joins pve, srv1 and my laptop. The VPS joins it too, and every connection between the VPS and srv1 travels inside it.
Tailscale Serve · 07
A Tailscale feature that publishes a local port to the rest of the mesh over HTTPS with a valid certificate. How I reach Stalwart's admin page without exposing it anywhere public.
TCP mode · 05
From the VPS design in the original part 05, never built. HAProxy forwarding raw bytes without interpreting the protocol, as opposed to HTTP mode. Required here because SMTP and IMAP are not HTTP.
TLS-RPT · 03
A DNS record giving an address where other servers report TLS failures when delivering to me. The companion to MTA-STS.
VPS · 01
Virtual private server: a small rented virtual machine with its own public IP. In this design it runs only HAProxy, Postfix and Tailscale, and is the only part that costs money.
Cloudflare Email Routing · 05
Cloudflare's free service that holds the MX records for a domain and receives its mail on Cloudflare's own servers. On its own it only forwards to another mailbox; with an Email Worker it can hand the raw message to code you write.
Email Worker · 05
A Cloudflare Worker with an email() handler. Email Routing calls it once per inbound message with the envelope and the unchanged raw bytes. Mine (worker/) speaks SMTP to Stalwart.
Workers VPC · 05
A beta Cloudflare feature, free on every plan, that lets a Worker open a plain TCP connection to any address reachable through a Cloudflare Tunnel you own. It is how the Worker reaches 127.0.0.1:25 on srv1 without a public port.
Resend · 05
A transactional email provider with a free tier (100 messages a day, 3,000 a month, no branding). Stalwart hands outgoing mail to it over authenticated SMTP on port 465, and it delivers from its own reputable IPs, signed as my domain.
Relay route · 05
Stalwart's name for "send through this other server instead of looking up MX records". Settings › MTA › Outbound › Routes, type Relay Host.
Outbound strategy · 08
The expression in Settings › MTA › Outbound › Strategy that picks a route per recipient. Mine reads: if the recipient domain is local, 'local', else 'resend'.
Reload server settings · 08
Management › Actions › Reload › Server settings. Most Stalwart configuration changes do nothing until this runs. Forgetting it cost a message two timed-out delivery attempts on 8 October.
_dc-mx record · 08
A name Cloudflare invents when an MX record points at a proxied hostname, so the MX resolves to something. It is a symptom that the MX target is wrong for mail, not a feature.
JMAP client · 05
A mail app that talks JMAP over HTTPS instead of IMAP. Twake Mail (Android, iOS), Sterna Mail and Ltt.rs (Android) all work against Stalwart through the tunnel at mail.22112002.xyz.
