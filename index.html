Running My Own Mail Server From Behind CGNAT

The homelab already serves websites through a Cloudflare Tunnel. This series is about the next thing I wanted: a real @22112002.xyz mailbox, hosted on the same VM, with no public IP of my own.

Same rules as the Homelab guides: wrong turns stay in, every "why not X" gets answered, and I prefer a command that produces a fact over a change that produces a hope.

The shape of the thing

Email is the one service where "just put it behind the tunnel" does not work, and the first page explains why. The short version: web traffic is pulled by a browser over HTTP, which Cloudflare Tunnel is built for. Mail is pushed by other mail servers over raw TCP on port 25, which no tunnel I can get for free will accept. So the design has two halves:

  • At home, on srv1: the actual mail server (Stalwart), the mailboxes, the spam filter, and the webmail (Roundcube) behind Caddy and the existing tunnel.
  • On a small rented VPS: nothing but a front door. It owns the public IP that the rest of the internet talks to, and it forwards every mail connection over Tailscale to srv1.

Where this picks up from

If you have not read the Homelab series, the relevant facts are: there is a Proxmox host (pve, 16 GB RAM) at home behind a CGNAT connection. On it runs a Debian 13 VM called srv1 with 2 vCPUs and about 4 GB of RAM. srv1 runs Caddy on port 80, PHP-FPM 8.4, MariaDB, and cloudflared, which holds an outbound tunnel to Cloudflare so that 22112002.xyz and lms.22112002.xyz are reachable from the internet. Tailscale connects pve, srv1 and my laptop. None of that changes in this series.
